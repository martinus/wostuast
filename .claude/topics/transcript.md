# The transcript: what it reads and where it lands

What Claude Code writes in a transcript and how it is read, a link to a turn, the "new" line, and a fetch against the push.

- **A link to a turn is `#<session>/<seq>`; `seq` is a place in one reading.** A session resumed from another directory counts from nought, so an old link may name a gone turn; `landOnBlock` then does nothing, and that is the whole failure. **It wins over landing at the foot once**: `state.turns.goTo` clears on landing, or a live session drags the reader back every second. **It runs in `landTranscript`, after `paint`, never in the draw** (#573): the clearing is a write, and a draw only reads `state`.
  - **`#<session>` alone is the session on screen**: `choose` writes it with `replaceState` (no `hashchange`), so a reload returns to it, not the first row. **Only when the address names another session**: always rewritten, a reply's link lost its `/<seq>` on opening. `test_a_reply_is_a_link_you_can_open_in_another_tab`.
  - **`seq` is digits only** (`placeInHash`): `Number("")` is 0, so `#s1/` linked the first block; `Number` also takes " 3", "1e2", "0x10". `test_a_link_to_a_block_is_digits_and_nothing_else`.
- **Coming back to a session lands on a "new" line over the first block after the reader last saw it** (#374), as Slack does. `state.turns.newSince` is the row's `seen_at` (#373), taken once by `markSeen` *before* it reads the session: after, it is now, and a turn ending under the reader's eyes would get a line. `undefined` is not taken yet, `null` no line, so a row arriving after the choice still gets it. In `blankTurns`, not `PLACE_FIELDS`: a visit's news is not kept.
  - **`putNewLine` puts the line on every draw, as the sibling just before the block's node, never inside it**, so `redrawBlock` keeps it; `patchTranscript` puts it when the first new block arrives by push.
  - **It says since when** (#398): "new since 08:27", with the day when not today (`newSince`, via `clock`, `dayOf`); "new" alone hid how much was missed. **A test reads the reader's last look before the page opens**: once open, the page marks it read and `store.seen` holds now.
  - **`landOnNew` lands again on each draw until the reader scrolls** (`newDown`): text is drawn, then much taller Markdown, and one landing left the line near the foot. A link (`goTo`) wins. A line too near the end stands where the pane lets it, which is right.
  - **A prompt right under it, or under "context compacted", draws no rule of its own** (#496, `:is(.divider, .newline) + .turn.mine`): the prompt's `::before` drew a second rule just below. A sibling selector, so the line stays the block's previous sibling. `test_a_prompt_under_the_compaction_line_draws_no_rule_of_its_own`.
  - **A test of "at the top" has two bounds** (`AT_TOP`): `top < 20` passed with the landing removed, the line 470 px *above* the pane. `test_coming_back_lands_on_a_line_over_the_first_turn_not_seen`, `test_the_line_holds_when_marked_comes_late`, `test_the_line_stays_and_lets_the_reader_scroll_away`, `test_a_turn_that_ends_while_you_watch_draws_no_line`.
- **A `user` record is not always a prompt.** Claude Code writes its own: one `/reload-plugins` is three or four records of tags, and `(no content)` was drawn as the reader's. `read_user_text` reads each for what it is: a command becomes one line saying what ran, the resumed-session caveat goes, a task notification or another session's message is a `note`, shown but never on the reader's rail. **A record is a command only when nothing else is on it**: a prompt asking about this feature can hold `<command-name>`. **Nor is an interrupt a prompt**: each Escape that stops a turn writes `[Request interrupted by user]` (`... for tool use]` after a declined dialog) as a `user` record, and each decline from the page drew a prompt and named a round. `INTERRUPTED` makes a record that is exactly that text a note. `test_an_interrupt_claude_code_wrote_is_a_note_not_your_prompt`.
  - **A task notification is its summary and its result** (`task_note`). Its fields: `task-id`, `tool-use-id`, `output-file`, `status`, `summary`, at times `note`, `result`, a `usage` of numbers; drawn minus the outer tag, 272 notes of tags on one machine (`wostuast shapes`). An unmeasured shape is shown as it came. **Another session's message is its words** (`AGENT_MESSAGE`): a header line in a `user` record, none in a queued one, the words in `<agent-message from=…>`, then a paragraph to the agent about the sender. **Read the record, not its skeleton**: the first fixture guessed the header away, and `shapes` caught it. Five shapes, 2.1.276 to 2.1.283, in `tests/fixtures/notes.jsonl`. `test_a_task_notification_and_another_sessions_message_read_as_words`.
  - **A `!` command is two records and one block.** `!git up` writes `<bash-input>git up</bash-input>`, then `<bash-stdout>...</bash-stdout><bash-stderr>...</bash-stderr>` with `<`, `>`, `&` as entities; neither is `isMeta`, so both showed as prompts, `-&gt;` and all. `BASH_INPUT` makes a `shell` block; `shell_output` adds the output with `html.unescape` (exact: `&` is escaped too), only to one not yet answered, or two runs merge. Only a record that is the tag alone, like `<command-name>`. Drawn on the reader's rail in the fixed face, output as text in `white-space: pre`; the map names the round `! git up`. 2.1.282, `tests/fixtures/bash_mode.jsonl`. `test_a_command_run_with_a_bang_is_one_block_with_its_output`, `test_a_bang_command_is_drawn_with_its_output_in_the_fixed_face`.
  - **A slash command is one block with its answer, in that shape.** No hook fires for one, so with "Set model to `Opus 5.5`" dropped as plumbing nothing said what `/model opus` did. `command_output` puts `<local-command-stdout>` into the `command` block, drawn as a `shell` one with `/` for `!`; "(no content)" closes it and draws nothing. **Both shapes are read**: 2.1.283 writes `/model opus` as `user` records, but `/model` closed without a pick, or `/context`, as `system` records (`subtype: local_command`, text in `content`), and `Transcript.add` read no `system` record but the compaction's. **Colour codes come off** (`ESCAPE_CODES`, then `CONTROL_CHARS`): `/context` draws its grid in them. A command nobody typed is a note.
    - **An `isMeta` record straight after an answer is the answer again**, as Markdown for the agent (`/context`'s numbers showed twice). `echo_of` drops it: only straight after, once, never after "(no content)": `/init` sends its prompt as an `isMeta` record with no answer before, and that is shown. `tests/fixtures/local_command.jsonl`.
    - **`<local-command-stderr>` is not read yet, on purpose: record one first.** The 2.1.285 bundle writes it for a failed command (`commandOutcome` `failed`), but none has been read on any machine, and `payloads.md` says a shape is recorded, never guessed.
    - `test_a_slash_command_and_what_it_answered_are_one_block`, `test_a_slash_command_is_drawn_with_what_it_answered`.
- **`wostuast report`'s transcript section (was `wostuast shapes`, #323) finds a new Claude Code shape before the reader does**: each such bug (`!git up`, `/clear`, `/model`, paste tags on the row) reached the reader as tags on screen. `transcript_shapes` reads recent transcripts through `Transcript.add` and lists records and pieces left out and not on `SILENT_RECORDS`, and Claude Code tags (`MACHINE_TAG_NAME`: a hyphen or underscore, which HTML has not) left in a prompt, note or command. Its first run found task notifications with inner tags and pasted images not drawn.
  - **A tag counts only when closed too, and in a prompt only when the prompt opens with it**: else it listed `<uint32_t>` from C++, `<commit-hash>` from skills, and bug reports quoting tags.
  - **Names and counts, never text**, so the output can go into a public issue as is.
  - **A name goes on `SILENT_RECORDS` only after a real record of it was read**: the queued message was an attachment nobody had looked at.
  - **It splits on `\n`, never `splitlines()`**: U+2028 in a string cut 17 records in half (the diff scar).
  - `test_shapes_lists_what_the_page_cannot_show_and_never_the_text`, `test_shapes_reads_only_the_days_asked_for`.
- **A message sent to a busy agent comes back wrapped, and the wrapper is not the reader's** (`QUEUED` keeps the middle). Claude Code queues it into the turn inside a `<system-reminder>`: a header (`The user sent a new message while you were working:`), the words, a footer to the agent. As a `user` record all three showed as the reader's prompt, the round named after the header; every send from this page to a working agent takes this shape. **Order matters**: the reminder tags come off first (`strip_reminder`), and the message is pulled out *before* `MACHINE_TAG`, whose list holds `system-reminder` and would take the message. **The header must open the record and the footer be there**, or someone quoting the wrapper to ask about it gets their question answered with its own quotation.
- **Pasted text comes off Claude Code's paste tags, by Claude Code's own rules.** A Claude Code that keeps a paste apart writes it after the typed text as two newlines, `<pasted_content id="1da8">`, the text, `</pasted_content id="1da8">`, and its screen hides them. Drawn, every review sent from here (newlines make it a paste) came back as tags under two blank lines, the round named after the tag. `unwrap_pastes` ports the bundle's reader (`Pct`): four lowercase hex digits, the same on both tags, each tag on its own line, up to two newlines either side belonging to the wrapper, anything else left as typed (someone asking about the tag types one). It runs first in `read_user_text`, so a paste in a queued message comes off too. **And in `_on_prompt`**: the hook gets the prompt as written, so the row read `prompt: <pasted_content id="3400"> I got...` beside a clean transcript. `test_the_row_shows_a_pasted_prompt_without_its_tags`. A feature switch decides the wrapping (2.1.281 here does not), so the shape comes from its source and the reader's record.
- **A message queued while the agent works is an `attachment`, and it is read.** 2.1.276 to 2.1.281 write a `queued_command` attachment and no `user` record (eighteen queued prompts on one machine, none elsewhere). `Transcript.add` read only `user` and `assistant`, so the agent answered words not on the page, mostly typed in this page's send box. `add_queued` reads it through `read_user_text`: `origin.kind` human is a prompt, a peer's message or a task's news a note; other attachments stay out. **One with no `commandMode` is a note** until such a record is read: all 441 on one machine (2.1.276 to 2.1.285) had it. A note is still shown; the reader's rail on words not theirs is the worse mistake. `test_a_message_queued_while_the_agent_works_is_drawn`.
- **`isMeta` is Claude Code speaking, never the reader.** A Stop hook's answer, a skill's body, "Continue from where you left off.", an image's caption came as `isMeta` `user` records, wore the reader's rail and named rounds. `user_block` makes them notes, for a string and for pieces. `test_what_claude_code_wrote_itself_is_never_your_prompt`.
- **Thinking is never drawn, and the daemon never makes it a block.** Most thoughts' text is not in the transcript (4,274 of 4,785 on one machine were a signature only), so a `t` that showed them mostly showed nothing and read as broken; the reader chose to drop thoughts and the key. `Transcript` returns no block for a `thinking` piece, so nothing can count, draw or search one. That ended a CSS workaround (a hidden thought was still a sibling to `+`; `pastThought`, `markNext`, and the `past-tool`, `past-words`, `next-tool` classes stood in): plain `+` and `:has(+ ...)` rules are right again. `test_thinking_is_never_a_block_even_with_text_in_it`, `test_a_thought_between_two_tool_calls_leaves_no_trace`.
- **Everything keyed on `seq` is forgotten together, in `forgetPlaces`.** `seq` is a place in one reading, not an identity: a rewritten transcript leaves `state.turns.open` and `state.turns.at` on different blocks; of three separate forgettings, two were wrong. **`run` is kept with a session's places**: `usePlace` restoring choices without their reading would make every return look like a rewrite. **The forgetting is guarded on `run !== -1`**: "none held yet" is every first load, and `goTo` comes from the address bar before it, so forgetting there dropped the link the page opened on. **That guard is one function, `takeRun`** (#544): the fetch (`loadTranscript`) and push (`onTranscriptPush`) each had their own. `test_a_reading_that_has_not_changed_forgets_nothing`, `test_a_rewritten_transcript_forgets_what_was_chosen_by_seq`.
- **The find box narrows the list, never the transcript**: taking turns out took the conversation round a hit, the reason to read it. `shownRounds` filters the left bar; `markHits` marks hits in place, since an unmarked hit scrolled past is missed.
- **A transcript fetch merges what was pushed while it was out.** The daemon snapshots under its lock and answers after, so a tick can push the next block first; the snapshot put in wholesale lost it, the next landed after a hole, and a text block is never pushed twice. `state.turns.early` keeps pushes landing during a fetch; they go over the snapshot by `seq`. **The list is the fetch's ticket; only the newest fetch lands**: after a quick Transcript-Session-Transcript two were out, pushes went into the second's list, and the first, answering last, put its older snapshot back. **A push from another `run` makes the snapshot stale, and it is fetched again**: the transcript was rewritten meanwhile. `test_a_block_pushed_while_the_transcript_is_fetched_is_kept`, `test_only_the_newest_transcript_fetch_lands`, `test_a_fetch_older_than_a_pushed_reading_is_asked_again`.
- **A stream opens by saying which `version` of the transcript the daemon holds** (`transcript_held`). A tick between a fetch's snapshot and the stream joining the hub sends to nobody, as does one during a reconnect, or into a stream the browser closed and the hub has not noticed. `Serving.stream` sends it after joining, so what is read after is pushed and before is counted; the page fetches when it holds less, or keeps it in `state.turns.told` for the fetch that is out. **`version`, never a block count**: a tool result goes into its call's block, so the count stays and a result read with no stream open was never fetched. `Transcript.version` moves on every read that changed something; every push and answer carries it. **The opening is decided before anything is written, and both go in one write**: the socket is unbuffered, so a reader that saw `sessions` could act (a tick starts reading the transcript) before the stream asked, and get an opening ahead of its block. `test_a_stream_decides_its_opening_before_it_says_anything`, `test_a_block_read_while_no_stream_was_open_is_fetched`, `test_a_tool_result_read_while_no_stream_was_open_is_fetched`.
  - **In a test, after `resubscribe` or `choose`, go through `renew_stream`**, which waits for the new stream's first word. `wait_for_watching` covers the gap above but not a stream just replaced: the daemon lists the closed one until a write fails, so it answers at once and the next push hits the dead socket.
  - **The opening carries the settings too**, after the sessions and the transcript, read under `config_lock` once the stream is in the hub. After its load a page gets settings only from `tell_config`'s pushes, and choosing a row opens a new stream: a change before it joined reached nobody, and old links stayed (`test_a_ticket_in_a_rows_name_or_branch_is_a_link` red by chance, #595). `read_events` skips a `settings` event unless asked, so a count of sessions stays one. `test_a_stream_opens_with_the_settings`.
  - **A stream too slow for its pushes is closed, never given a gap.** `Client.put` silently dropped the oldest message at `CLIENT_BACKLOG`; pushes hold only changed blocks, so the page lost one, its `version` passed it, a fetch got `same`, and a reconnect's opening was not ahead (measured: pushes 3, 4 and 6 to 11 never came, the stream went on). Now the first message it cannot keep sets `Client.lost`, empties the queue, and `stream` closes without writing again. **Closing on the next write is not enough**: anything sent after the lost push carries the page past it. The browser reconnects and the opening makes it fetch (#235). `test_a_stream_too_slow_to_keep_up_is_closed_and_never_given_a_gap`, `test_a_push_the_stream_could_not_keep_is_fetched_after_it_closes`.
- **A failed transcript fetch is not an empty transcript.** `ask` gives null, and the page drew "Nothing in this transcript yet.", forgot the reader's places, and never asked again (the tab polls nothing). Now what is held stays, an empty tab says it could not read the transcript, and it retries after `TRANSCRIPT_RETRY`. **One timer, `state.transcriptRetry`, cleared by every fetch**: each tab switch into a failing fetch started its own loop, and all fetched the whole transcript when the daemon came back (`test_failing_fetches_keep_one_retry_not_one_each`). **A push with nothing held is placed by `seq`**: it holds only changed blocks, and assigned whole put block 3 at index 0. `test_a_transcript_fetch_that_fails_keeps_what_is_held`.
- **`drawTranscript` has no redraw key, on purpose.** The live path is `patchTranscript`, which appends; a full draw comes only from a tab switch, a session or a find-box key, and each wants the blocks rebuilt. A key would also leave an arriving block's `fresh` class on for ever: a redraw is not an arrival. `test_only_a_block_that_has_just_arrived_slides_in`.
  - **The drawn nodes live on the pane, not in `state`** (#573): `pane.nodes`, one per block, and `pane.heads`, the line over each run of calls; written into `state.turns`, the draw broke principle 3. **The pane says which transcript it was drawn from** (`drawnFrom`, read via `drawnTurns`, `turnNode`): `choose` blanks `state.turns` but the pane keeps the last session's nodes until the fetch lands, and a push meanwhile is patched at once. `patchTranscript` redraws the tab for a pane drawn from other turns (blanking nodes in `blankTurns` used to do this unsaid). `test_a_push_after_a_switch_patches_no_node_of_the_last_session`.
- **`state.turns.down` is read before the pane is emptied**: `replaceChildren` puts the scrollbar at nought, which the scroll listener would record as the place. The listener is attached once per pane (`pane.dataset.watched`): `drawTranscript` runs many times over one pane, and `split` rebuilds it only on a tab change.
  - **It writes only for the session whose blocks the pane holds** (`pane.dataset.session`): `choose` leaves the old blocks until the new land, and a scroll between (the browser fires one when the send box goes) became the new session's place, the `.filescroll` scar again. **An empty draw claims no session**: it drops the scrolled blocks, the bar falls to nought, and that became the place of a session whose fetch failed. `test_a_scroll_left_over_from_another_transcript_is_not_its_place`, `test_a_failed_fetch_does_not_take_a_sessions_place`.
  - **`null` is "no place kept"; nought is the very top**: one number for both sent a reader at the top to the foot on every find-box key. `test_the_top_of_the_transcript_is_a_place_too`.
  - **The foot is `null` too, never its pixels**: the first load draws text, then much taller Markdown once `marked` arrives, and the text draw's foot as a number left the reader thousands of pixels short of the latest reply. `nearBottom` decides. `test_a_first_load_lands_at_the_foot_when_marked_comes_late` holds `marked` until the text draw is done.
  - **The map keeps its own place across a rebuild** (`drawTurnList`, on every arriving round), as emptying a list scrolls it to the top. At its foot or new to the session, it lands at its foot; scrolled up, it stays. `list.dataset.session` says whose map it was. `test_the_map_keeps_its_place_when_a_round_arrives`.
- **The search redraws the whole tab, so it has to put the reader back.** `drawTranscript` ends at the foot, right for a session with no kept place: the agent's last words are what you came for.
- **One block redrawn alone is still marked.** `redrawBlock` is the Transcript tab's `fillDiffFile`: it does to a node all that `drawTranscript` does, or that block loses what the others keep.
